# judge_net 设计文档

> 本文件阐述 judge_net 网络冲突法官智能体的设计哲学、架构决策与黑天鹅奖叙事。
> 面向评审者、维护者与对设计感兴趣的用户。

## 一、问题痛点：网络冲突的"旁观者困境"

互联网降低了表达门槛，也放大了冲突烈度。当一场网络争吵发生时：

- **当事方**陷入"当局者迷"，情绪驱动论证，难以看见自身谬误。
- **旁观者**缺乏对议题的深入认知与对论证结构的分析能力，常被话术带节奏，难以做出公平判断。
- **平台**只管内容合规与否，不评判对错。
- **专业仲裁**（法律、调解）成本高，触达不到日常网络口角。

结果是：大量网络冲突在"各说各话—情绪升级—群体站队—群体性撕裂"的路径上耗散，伤害网络生态与个体心理。

**judge_net 的切入点**：用一个 AI 法官补位"旁观者理性分析"的空缺——不对当事人下道德判决，不对抗平台合规，而是给争议一份结构化、有信源、可上诉的技术性裁决。

## 二、核心设计哲学

### 2.1 网络和谐健康优先于争论输赢

这不是一句口号，而是贯穿设计的硬约束：

- 拒裁清单（`safety_refuselist.md` R1-R6）会主动中止裁决，转介专业资源——因为有些冲突不该被裁决。
- 应答话术模式默认推荐"降温退场"而非"反击升级"。
- 建设性建议是裁决报告的强制节，不能省略。

### 2.2 不各打五十大板

伪装中立是最大的不公正。设计上强制：

- A/E/F 类争议必须给出"较正确一方"判定（事实层面）。
- 价值分歧议题必须显式声明"不裁决对错"，而非模糊处理。
- 回归测试有全局断言：至少一案例出现"较正确一方"，否则判定失败。

### 2.3 不冒充真理裁判

裁决权有边界：

- 价值/审美/道德取向只澄清前提差异，不判对错。
- 不可核实事宜显式写"无法核实"，不装作全知。
- 模型偏见透明声明，敏感议题提示读者。

### 2.4 三层分析框架

争议被拆解为三个正交维度，避免混为一谈：

| 维度 | 处理对象 | 工具 |
|---|---|---|
| 事实层 | 主张是否为真 | `source_credibility.md` 信源分层 |
| 逻辑层 | 论证是否成立 | `fallacy_taxonomy.md` 21 谬误 |
| 情绪修辞层 | 是否用不正当手段 | 6 类修辞战术 |

事实错误不算谬误，情绪本身不是错误——三者各司其职，互不替代。

## 三、架构决策：低代码路线

### 3.1 为什么选智谱清言自定义智能体

| 维度 | 智谱清言智能体 | 自建 FastAPI |
|---|---|---|
| 用户无权限体验 | 分享链接直聊 | 需部署 + 鉴权 |
| 联网检索 | 平台内置工具 | 自接 API + Key 管理 |
| 视觉 OCR | GLM-4V 原生 | 自接 vision API |
| 多轮上诉/话术 | 对话记忆天然 | 自建 session |
| 黑天鹅奖导向 | 产品思维 | 工程炫技 |
| 评委体验 | 点链接即用 | HF Spaces 冷启动 |

往届获奖作品（`https://chatglm.cn/share/Fjl8C`）即是此形态，证明可行。

### 3.2 提示词即架构

所有逻辑沉淀在 `system_prompt.md`（558 行）+ `knowledge/*.md`（7 个文件 1181 行）中：

- 主提示词提供流程与原则。
- 知识库文件提供细节与字面模板。
- 冲突时以主提示词为准。

### 3.3 双交付物策略

- **智谱清言智能体分享链接**：用户即点即用，零门槛。
- **GitHub 仓库**：版本管理提示词、知识库、金标准案例、设计文档、回归脚本，体现工程严谨性，便于迭代。

## 四、原始构想的五个环节与拓展

用户原始构想包含五个环节，本设计在各环节上的拓展点如下：

### 4.1 多模态输入（截图 + 文本）

- **原始**：复制对话或上传截图。
- **拓展**：OCR 后强制"预处理摘要"让用户确认发言方归属，避免错认主体；多图按时间拼接去重；剥离 UI 噪声（点赞、表情包、时间戳）。

### 4.2 主题识别与即时研究

- **原始**：搞清事件内容，基于知识储备 + 即时研究。
- **拓展**：议题域名分类（9 类，区分可判对错与价值分歧）；即时研究三件套（权威信源检索 + 信源分层 + 时效标注）；知识截止警示——无信源时显式声明"无法核实"，杜绝幻觉。

### 4.3 冲突形式量级

- **原始**：诚意争辩 / 偶发冲突 / 预谋攻击。
- **拓展**：形式化为 A–F 六类（诚意争辩、偶发口角、CIB 协同造假、营销引流、阴谋论、谣言 AI 骗局），每类对应不同裁决深度与降温路径，附决策树。

### 4.4 三层对话分析

- **原始**：知识信息筛查 + 逻辑问题辨别 + 情绪化输出排查。
- **拓展**：事实层四态（已证实/已证伪/存疑/无法核实，附信源）；逻辑层 21 谬误分类法 + 标注格式；情绪层识别修辞战术（煤气灯、DARVO、关心式钓鱼等）而非贴情绪标签。

### 4.5 特殊形式化解

- **原始**：水军、阴谋论、谣言、AI 化骗局。
- **拓展**：四类特殊情形检测器（CIB 信号、AI 内容信号、阴谋论叙事签名、谣言查无信源），每类有明确触发条件与处理策略；阴谋论走逐条证伪而非陷入"证明不存在"陷阱。

## 五、关键创新点

### 5.1 上诉机制（局部重审）

不同于"再判一次"，judge_net 要求用户指明不服条目 + 提供新证据，只做局部重审，输出"二审备忘录"。这保证了裁决稳定性与可解释性。

### 5.2 应答话术模式（opt-in + 护栏）

双刃剑的平衡：用户须显式 opt-in + 接受 4 条条款；7 类内容绝对禁止生成；5 种风格默认推荐"降温退场"；话术必须基于已核实事实且 ≤300 字。

### 5.3 公众人物阈值

有限度了解的边界形式化：维基百科条目或认证粉丝 >10 万；只调查与争议直接相关的公开信息；禁止调查私生活；非公众人物一律不查。

### 5.4 回归测试

用金标准案例集（5 个匿名化中文社交语境）+ paratera GLM-5.2 API 跑回归，断言 12 节结构 + 关键判定 + 禁止行为，CI 化提示词迭代。

## 六、黑天鹅奖叙事

> 黑天鹅奖鼓励"发现现有应用痛点并进行改造"。

**痛点**：网络争论旁观者缺乏公平判断能力，现有 AI 助手要么回避裁决（"两边都有道理"），要么各打五十大板（伪中立），要么助长对立（给用户写对线话术）。

**改造**：judge_net 不回避裁决——用三层分析框架 + 信源分层 + 谬误分类法，给出有据可查的较正确一方判定；同时以"网络和谐"为最高原则，内置拒裁清单与降温优先策略。

**产品思维**：智谱清言分享链接交付，用户零门槛体验；GitHub 仓库开放设计哲学与回归测试，体现可迭代性。

## 七、局限与未来工作

### 7.1 当前局限

- **联网检索依赖平台**：智谱清言内置搜索质量决定信源上限。
- **OCR 受视觉模型能力限制**：复杂截图（多图拼接、长截图）可能漏识别。
- **回归测试样本量小**：5 个金标准案例覆盖主要类型，但未覆盖所有边界。
- **无持久记忆**：上诉须在同一会话内完成。

### 7.2 未来拓展点

- 接入更多信源（学术数据库、政府公开数据 API）。
- 金标准案例扩充至 20+，覆盖更多边缘情形。
- 多语言支持（英文争议的裁决）。
- 上诉历史的持久化（同一争议跨会话二审）。
- 与平台合规系统联动（CIB 信号自动举报）。
